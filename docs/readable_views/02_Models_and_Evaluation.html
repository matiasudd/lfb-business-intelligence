02 — Models, reference and retrospective evaluation

The final study retains logistic regression. It compares the original C2 specification and later richer dispatch information on the same test mobilisation records. A weak precision remains part of the conclusion. The simple reference always predicts under ten minutes.

1. Ordered feature pipeline and availability

1. Read the same eligible snapshot and fix target = AttendanceTimeSeconds >= 600.

2. Derive calendar and strictly earlier-dispatch context (experiment.py, extra_logistic.py, features_v2.py).

3. Join official incident locations many-to-one, keeping unmatched rows (location_features.py).

4. Add training-ground and station-postcode distance proxies (station_geography.py).

5. Compute grouped histories from arrivals strictly before the current dispatch (rolling_outcomes.py).

6. Fit one-hot categories, numeric imputation/scaling and the classifier on training only. Choose cut-offs using validation, then score frozen test choices.

The method files are preserved in src/method_record/, with file hashes in MANIFEST.json. The private feature cache below is not part of the submitted repository. Its source snapshot and event-time checks establish which process it records. A later location revision or a 2025 station address is not automatically a verified 2023 dispatch-time value, so the enriched branch is conditional retrospective evidence.

3. Refit the selected pipeline with explicit settings

The categorical/numeric feature lists below are the actual frozen selected configuration. Categories include calendar/origin/destination context and interactions. Numeric fields include distance/load proxies and past-only response histories. Direct outcomes of the current row are excluded. Standardisation and imputation learn only from training.

C=0.002 controls regularisation; it is different from the score cut-off and the 600-second outcome definition. Balanced class weights mean scores should not be presented as independently calibrated probabilities.

4. Score threshold: maximise validation precision with recall at least 85%

The positive outcome remains at least 600 seconds. The score threshold below is chosen using validation labels/scores, with the larger threshold resolving precision ties. Its actual validation recall need not equal its later test recall. Do not retune after seeing test results.

p,r,t=precision_recall_curve(validation.target,validation_scores)
p,r=p[:-1],r[:-1]
eligible=np.flatnonzero(r>=.85-1e-12)
winner=eligible[np.lexsort((t[eligible],p[eligible]))[-1]]
threshold=float(t[winner])
assert np.isclose(threshold,0.34265157602812196,rtol=0,atol=1e-8)
print('Frozen classification score cut-off:',threshold)
print('Validation precision:',p[winner],'Validation recall:',r[winner])
def measures(y,pred):
    tn,fp,fn,tp=confusion_matrix(y,pred,labels=[0,1]).ravel()
    precision=tp/(tp+fp) if tp+fp else np.nan
    recall=tp/(tp+fn)
    return {'TN':int(tn),'FP':int(fp),'FN':int(fn),'TP':int(tp),'precision':precision,'recall':recall,
            'accuracy':float((tn+tp)/len(y)),'alerts':int(tp+fp)}
selected=measures(test.target,test_scores>=threshold)
assert [selected[k] for k in ['TN','FP','FN','TP']]==[61264,33551,988,6445]
display(pd.DataFrame([selected],index=['Selected expanded logistic']))

Supported conclusion

The selected model obtains 86.71% recall and 16.11% precision in the observed retrospective test. It misses 988 of 7,433 long cases and emits 39,996 alerts, including 33,551 false positives. It remains an experimental flag, not evidence that staffing/dispatch changes reduce arrival times. The monthly recall ranges below 85% in one month, so a full-period minimum is not a monthly guarantee.

Priority improvement: verify source fields at dispatch, obtain route/resource context if available, and test a later unexamined period. Better results are not guaranteed by these proposed inputs. Continue with notebook 03 for the implemented visual system and decision trace.
